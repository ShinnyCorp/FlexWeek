# Logic that stays in the interface

The engine ports the planning and the Qt-free helpers. Anything that builds or paints a Qt widget stays in Python. This document maps, on v0.17.2, every decision the interface code still makes in Python, so a later rewrite of the interface in Rust (item E7 of `docs/engine/contract.md`) knows what is decided, where (file and function), and which tests cover it. Nothing here moved. Nothing in this document changes any code.

How it was built. Every Python file under `desktop/native/` that imports PySide6 was read in full, plus `look.py`, `layouts/registry.py`, `autostart.py`, `kept.py`, `tones.py`, and `version.py`, which stay in Python because they write stylesheets, sounds, or the process environment. A function is listed when it decides something (compares, computes, picks between outcomes, words a message a student reads, clamps, sorts, or holds a rule), not when it only builds or paints widgets. Private helpers (`_name`) are listed when they hold a rule. Each name was checked to exist, and each cited test was checked to exist, by script. Nothing was run: the "test" column says which test reaches the function, from reading the test, and does not claim the test passes today.

Reading the test column. `desktop/tests/<file>::<test>` is a test that calls the function or asserts its result. `(via <caller>)` means the test reaches the function only through that caller, so a change in the function would show up there but the test does not name the rule. `none found` means no test in `desktop/tests/` that calls it or asserts its result was found.
